## Findings that intentionally have NO plan (observed, not actioned)

- **Uncommitted work in the working tree.** `git status` shows 6 modified
  component files plus two untracked new components (`ModeToggle.tsx`,
  `FormatQualitySelects.tsx`) — an in-flight UI refactor extracting select
  controls out of `UrlInput.tsx`. It type-checks and tests pass. Commit it
  before starting any plan so plan diffs stay reviewable.
- **`python-engine/engine.py` is 1,508 lines.** A monolith (download,
  metadata embedding ×4 codecs, verification, thumbnail selection, retry,
  deno discovery all in one file). It has tests and works; splitting is a
  nice-to-have refactor, not a priority. Do it only when adding a feature
  that touches the file anyway.
- **Express 4 → 5 migration.** ~~`web/middleware/static.mjs` uses
  `router.get("*")`, which breaks under Express 5's path-to-regexp v8.~~
  **RESOLVED (2026-09-01):** Dependabot bumped `web` to Express 5.2.1, which
  would have crashed the server at startup. Fixed with the `/{*splat}`
  wildcard; regression test in `web/tests/static.test.mjs` (CI backend job).
- **Frontend test suite is slow (~55s)** due to jsdom setup overhead in
  Vitest. Functional, not worth optimizing now.

## Conventions every executor must follow

- Frontend: React 19 + TypeScript strict mode, Zustand stores, Tailwind v4.
  Match existing component patterns (see `src/components/`).
- Backend: plain ESM `.mjs`, no TypeScript, no new dependencies unless the
  plan says so. Error style: `res.status(N).json({ error: "..." })`.
- Tests: Vitest for frontend (`src/**/*.test.{ts,tsx}`, jsdom, setup in
  `src/test/setup.ts`), plain `node:assert` scripts for backend
  (`web/tests/*.test.mjs`), pytest for Python (`python-engine/tests/`).
- Comments in this repo are detailed and explain *why*, not *what*. Match
  that style.
